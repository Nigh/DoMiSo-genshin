## Project Overview

DoMiSo Universal is a Wails 3 desktop application that parses DoMiSo text notation into MIDI and plays it back through a piano roll visualization powered by a forked [signal](https://github.com/ryohey/signal) editor.

## Key Conventions

### Go Backend

- Module name: domiso-universal
- All Go code is in the root package (package main)
- `app.go` contains AppService with methods bound to the frontend via Wails:
  - `ParseTextToMIDI(text)` — parse DoMiSo notation → MIDI bytes
  - `ParseSheetStats(text)` — parse and return note count, measure count, duration, BPM
  - `ImportSheet(filePath)` — read file from disk, auto-detect format (txt/json/dms), validate size (max 1MB)
  - `ExportSheet(filePath, meta, notation)` — write file to disk as JSON or TXT with header meta
  - `ListFreeSheets()` — list embedded sample sheets (supports .txt, .json, .dms)
  - `LoadSheet(filename)` — load a single embedded sheet by path
  - `FormatDuration(seconds)` — format seconds as `M:SS`
- Key types: `SheetInfo`, `SheetMeta`, `SheetJSON` (version 1 format), `SheetStats`, `ImportResult`
- `free_sheets/` is embedded via `//go:embed all:free_sheets` — sheets are compiled into the binary, not read from filesystem
- The parser is `github.com/Nigh/domiso-parser` — Parse(), WriteMIDI(), ParseDoMiSo()
- Go version: 1.25+

### React Frontend

- Wails bindings are auto-generated in frontend/bindings/domiso-universal/ — **NEVER edit these files**
- Import bindings as: import { AppService, SheetInfo } from "../bindings/domiso-universal"
- ParseTextToMIDI returns a base64-encoded string (Wails serializes []byte as base64)
- The frontend uses @wailsio/runtime for Wails integration (Dialogs.OpenFile, Dialogs.SaveFile)
- No additional UI framework — inline styles, React 18
- Editor uses overlay-based syntax highlighting (textarea + pre with synchronized scroll)
- Syntax highlighting: `src/utils/highlight.ts` — highlights DoMiSo notation (notes, commands, headers, chords, tuplets)
- Components:
  - `CodeEditor` — syntax-highlighted code editor with line numbers
  - `MetaEditor` — sheet metadata form (title, composer, arranger, tempo, time sig, key, description)
  - `StatusBar` — bottom bar showing note count, measure count, duration, BPM, format
  - `SheetSelector` — sidebar list of embedded sample sheets
  - `Toolbar` — top bar with Editor/Piano mode toggle, Open/Save/Sync buttons, playback controls

### Signal Submodule

- signal/ is a **git submodule** pointing to git@github.com:Nigh/signal.git (our fork)
- After git clone, run git submodule update --init to check out signal
- Built independently with its own package.json and npm workspaces
- Key modifications from upstream signal (committed in the fork):

  - pp/src/index.tsx: Removed Sentry, added bridge init, exported rootStore
  - pp/src/hooks/useAuth.tsx: Stubbed AuthProvider (no Firebase)

  - pp/src/stores/RootStore.ts: Local SoundFont URL (./soundfonts/A320U_drums.sf2)
  - pp/src/stores/SoundFontStore.ts: Local SoundFont URL (./soundfonts/A320U.sf2)

### Data Flow

```
1. User selects/types DoMiSo notation in the text editor
2. Clicks "Sync to Piano" button
3. Frontend calls AppService.ParseTextToMIDI(text) via Wails binding
4. Go backend: domisoparser.Parse(text) → Score → WriteMIDI() → []byte
5. Wails returns []byte as base64 string
6. Frontend decodes base64 → Uint8Array
7. postMessage({ type: "LOAD_MIDI", data: Array.from(midiBytes) }) to signal iframe
8. Signal bridge.ts: songFromMidi() → rootStore.songStore.song = song
9. Signal's piano roll renders notes, user can play/stop
```

### JSON Sheet Format

```json
{
  "version": 1,
  "meta": {
    "title": "Song Title",
    "composer": "Composer Name",
    "arranger": "Arranger Name",
    "description": "Description text",
    "tempo": "120",
    "timeSig": "4/4",
    "key": "C"
  },
  "notation": "1=C 4/4 120\n1 2 3 4 | 5 6 7 1"
}
```

### File Import/Export

- **Import** (Open button): Supports .txt, .json, .dms formats via `AppService.ImportSheet(filePath)`
  - DMS files are decrypted using domiso-parser's DecryptDMS()
  - JSON files extract meta and notation separately
  - TXT files are loaded as-is; meta is parsed from header lines (标题:, 记谱:, etc.)
  - File size limit: 1MB (enforced in Go backend)
- **Export** (Save button): Default JSON format via `AppService.ExportSheet(filePath, meta, notation)`
  - JSON export includes version, meta object, and notation string
  - TXT export writes meta as header lines followed by separator and notation

### postMessage Protocol

| Direction | type | data | Description |
|-----------|------|------|-------------|
| signal → parent | SIGNAL_READY | none | Signal iframe loaded and ready |
| parent → signal | LOAD_MIDI | { data: number[] } | MIDI bytes as array |
| signal → parent | MIDI_LOADED | { success: boolean, error?: string } | Load result |

## Build Order

1. Signal packages: 
pm run build -w packages/player then 
pm run build -w packages/dialog-hooks
2. Signal app: 
pm run build -w app
3. Copy signal dist: signal/app/dist/* → rontend/public/signal/
4. Frontend: 
pm run build (in rontend/)
5. Go binary: wails3 build or go build -o bin/domiso-universal.exe .

## Important Notes

- **Never commit** rontend/bindings/ — auto-generated by Wails
- **Never commit** rontend/public/signal/ — copied from signal build
- **Never commit** signal/app/public/soundfonts/*.sf2 — downloaded during build
- **Never commit** signal/node_modules/ or signal/app/dist/
- The ree_sheets/ directory IS committed — its contents are embedded into the binary
- Go's `embed.FS` does not accept filenames with `'` (ASCII apostrophe U+0027) — use Unicode MODIFIER LETTER APOSTROPHE `ʼ` (U+02BC) in filenames instead, and `unescapeSheetName()` in `app.go` converts it back to `'` for display
- signal/ is a git submodule — modifications go to git@github.com:Nigh/signal.git
- Signal's @signal-app/core exports TypeScript source (no build step needed)
- Signal's @signal-app/player requires 	sc build before the app can build
- Signal's dialog-hooks package requires 	sc build before the app can build

## When Modifying Go Service Methods

After adding/removing/renaming methods on AppService in pp.go:
1. Run wails3 generate bindings -clean=true -ts
2. Update rontend/src/App.tsx to use new binding signatures
3. The bindings directory name matches the Go module name

## When Modifying Signal

After changing signal source code:
1. Make changes in signal/ directory
2. Commit and push to the signal fork: cd signal && git add -A && git commit -m "..." && git push
3. Update submodule ref in parent: cd .. && git add signal
4. Build signal: cd signal && npm run build -w app
5. Copy dist: signal/app/dist/* → rontend/public/signal/
6. Rebuild frontend: cd frontend && npm run build
7. Rebuild Go binary: go build -o bin/domiso-universal.exe .

## Known Limitations (MVP)

- No game auto-play (reserved for future)
- @ and | characters in sheets are silently ignored by parser
- Firebase/community features from upstream signal are stripped
